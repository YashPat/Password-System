# TUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the prompt-based CLI with a colorful, roomy Textual TUI for generate / recover / quit, keeping password derivation byte-for-byte identical.

**Architecture:** The hashing core gains an optional progress callback and quiet calibration; a pure `progress.py` turns (done, total, elapsed, now) into display strings; `tui.py` is a Textual app with four screens (Menu, RecoverInput, Computing, Result) running the hash in a thread worker. `main.py` launches the TUI, with `--plain` keeping the old CLI.

**Tech Stack:** Python 3.15, Textual 8.2.8, unittest (+ Textual `App.run_test()` pilot via `unittest.IsolatedAsyncioTestCase`).

**Spec:** `docs/superpowers/specs/2026-11-15-tui-design.md`

## Global Constraints

- Password derivation must not change: `test_passwords.py` must pass after every task.
- No passwords or keys written to disk.
- UI must not slow hashing measurably: UI updates only between 5,000,000-iteration chunks.
- Look: dark background; mint green primary; violet/pink and peach accents; rounded panels; generous padding; stat rows on the computing screen separated by blank lines.
- Dependency: `textual==8.2.8` only (drop unused `tqdm` from `requirements.txt`). Local venv at `.venv/` (git-ignored).
- Run tests with: `.venv/bin/python -m unittest -v`

## Review Focus

- Pasted keys with surrounding whitespace, a trailing newline, or invalid JSON → inline error message on the input screen, never a crash. (Task 4: `test_invalid_keys_show_error`, `test_keys_with_whitespace_accepted`)
- Quitting mid-computation → confirmation; on confirm the worker stops at the next chunk and the app exits promptly, not after 15 h. (Task 5: `test_quit_mid_computation_cancels`)
- Tiny workloads (iterations = 1) and elapsed = 0 → no division by zero; shows 100 %. (Task 2: `test_zero_elapsed`, Task 1: `test_callback_single_iteration`)
- Clipboard unavailable (no `pbcopy`, e.g. over SSH) → falls back to Textual OSC 52 copy and still notifies; password stays visible. (Task 4: `test_copy_falls_back_without_pbcopy`)
- Small terminal (80×24) → all screens readable, nothing clipped that matters. (Task 5: manual check via Herdr)

### Task 1: Progress callback and cancellation in the hashing core

**Files:**
- Modify: `password_recovery.py`, `password_generator.py`, `config.py`
- Test: `test_passwords.py`

**Interfaces:**
- Produces:
  - `ProgressCallback = Callable[[int, int, float], None]` in `password_recovery.py` — args `(done, total, elapsed_seconds)`; may raise `ComputationCancelled` to stop.
  - `class ComputationCancelled(Exception)` in `password_recovery.py`.
  - `_perform_iterative_hashing(seed_bytes, iterations, show_progress=True, on_progress: ProgressCallback | None = None) -> bytes` — when `on_progress` is given it is called after every chunk (including the last) and nothing is printed.
  - `recover_password(seed, iterations, on_progress=None) -> str | None` — `ComputationCancelled` propagates (not swallowed by its `except Exception`).
  - `create_password_with_keys(on_progress=None, verbose=True) -> tuple[str, str, int]`
  - `config.calibrate_iterations(target_time=TARGET_COMPUTATION_TIME, verbose=True) -> int` — `verbose=False` prints nothing.

- [ ] **Step 1: Write failing tests** in `test_passwords.py`, class `ProgressCallbackTest`:
  - `test_callback_does_not_change_password`: for each `KNOWN_KEYS` entry, `recover_password(seed, n, on_progress=lambda *a: None) == expected`.
  - `test_callback_reports_chunks`: with `n = 12_000_000`, collected `done` values == `[5_000_000, 10_000_000, 12_000_000]`, every `total == n`, elapsed values non-decreasing.
  - `test_callback_single_iteration`: `n = 1` → exactly one call with `done == total == 1`.
  - `test_cancel_propagates`: callback raising `ComputationCancelled` → `recover_password` raises `ComputationCancelled`.
  - `test_callback_mode_prints_nothing`: stdout captured with `redirect_stdout` is empty.
  - `test_quiet_calibration`: `config.calibrate_iterations(1.0, verbose=False)` prints nothing and returns int > 0.
- [ ] **Step 2: Run** `.venv/bin/python -m unittest test_passwords -v` (create venv first: `python3 -m venv .venv`) → new tests FAIL (unexpected keyword `on_progress`).
- [ ] **Step 3: Implement** the interfaces above. Restructure so the existing printing progress line becomes one callback implementation used when `show_progress=True` and `on_progress is None`; the chunk loop is shared.
- [ ] **Step 4: Run** tests → all PASS, including `KnownKeysTest`.
- [ ] **Step 5: Commit** `git commit -m "Add progress callback and cancellation to hashing core"`
